### Google AI Studio / GitHub 개발 에이전트 실행 명세

- 대상 프로젝트: 업로드된 `영어어플.zip`의 Android Kotlin + Jetpack Compose 프로젝트
- 기존 마스터 지시서: `영어학습앱_디자인_기능개선_에이전트_지시서.md`
- 이번 개정의 핵심: 단어 학습을 앱의 중심 경험으로 강화하고, 이미지 연상·능동 회상·간격 반복을 게임형 미션과 포인트 시스템으로 연결한다.
- 개발 원칙: 기존 기능과 사용자 데이터를 보존하면서 단계별로 실제 구현하고 검증한다.

# 0. 에이전트 역할과 최종 목표

당신은 시니어 Android 엔지니어, 학습 경험 설계자, 게임 시스템 디자이너, 데이터/QA 엔지니어 역할을 함께 수행한다.

이번 작업은 단순히 카드 색상을 바꾸거나 포인트 숫자를 화면에 추가하는 작업이 아니다.

**사용자가 영어 단어를 재미있는 게임을 하듯 매일 학습하고, 이미지와 장면으로 의미를 기억하고, 정답을 직접 떠올리고, 복습을 완료하며, 실제 학습 성과에 따라 포인트·레벨·배지를 얻는 완결된 단어 학습 게임을 구현하는 작업이다.**

반드시 지킬 원칙:

1. 기존 단어 데이터, AI 회화, 여행 회화, 발음 분석, 학습 기록, Firebase/Cloudflare 연동을 임의로 삭제하지 않는다.
2. 새 시스템을 추가하기 전에 기존 구현을 분석하고 재사용한다.
3. 포인트는 실제 학습 행동과 검증된 결과에 대해서만 지급한다.
4. 단어를 화면에 띄우거나 버튼을 반복 클릭하는 것만으로 포인트를 무한 획득할 수 없어야 한다.
5. 이미지가 없는 단어도 학습할 수 있어야 한다. 이미지 생성/다운로드 실패 때문에 학습을 막지 않는다.
6. AI가 만든 연상 이야기, 어근 분석, 발음 연결은 정확성을 검토할 수 있어야 한다. 허위 어원·억지 발음을 사실처럼 제시하지 않는다.
7. “해마학습법”은 앱에서 사용하는 기억 연상 학습 콘셉트/명칭으로 취급한다. 특정 그림이 해마에 각인된다거나 기억력이 몇 배 증가한다고 과학적으로 보장하는 문구를 쓰지 않는다.
8. 기존 저장 데이터와 사용자의 포인트·학습 이력을 마이그레이션 없이 초기화하지 않는다.
9. 실제 빌드와 테스트를 실행하지 않고 완료했다고 보고하지 않는다.
10. 외부 API, 유료 이미지 생성, 서비스 권한, 데이터 삭제, 보안 규칙 변경은 사용자 승인 없이 실행하지 않는다.

# 2. 제품 콘셉트와 핵심 사용자 경험

## 2.1 제품 콘셉트

**“단어를 외우는 앱”이 아니라 “단어를 모으고, 장면을 기억하고, 미션을 깨며 성장하는 영어 단어 어드벤처”**

사용자는 매일 다음 루프를 반복한다.

```text
오늘의 모험 입장
   ↓
오늘의 단어 미션 확인
   ↓
그림/장면으로 단어 의미 발견
   ↓
영어 발음 듣기 + 짧은 연상 스토리
   ↓
뜻을 가리고 직접 회상
   ↓
선택형/입력형/듣기형 미니 퀴즈
   ↓
틀린 단어와 애매한 단어 재도전
   ↓
오늘 미션 완료
   ↓
XP/코인/배지/연속 학습 보상
   ↓
다음 복습 일정 자동 등록
```

학습이 중심이고 게임 보상은 학습을 돕는 수단이다. 게임을 위해 학습량을 과도하게 늘리거나 포인트 때문에 무의미한 반복을 유도하지 않는다.

## 2.2 핵심 화면 구조

기존 하단 내비게이션은 우선 유지한다. 단어 탭을 열었을 때 기존 암기/퀴즈/패턴 탭을 단순히 나열하는 대신, 다음의 카드형 단어 학습 허브를 기본 진입 화면으로 개선한다.

1. 상단: 오늘의 레벨·XP·코인·연속 학습일
2. 중앙: 오늘의 핵심 미션 카드
3. 다음: 복습할 단어 카드(복습 due count)
4. 다음: 이미지 연상 단어 학습 시작 카드
5. 다음: 단어 퀘스트/보스 챌린지
6. 하단: 단어 모음집·배지·학습 기록 진입

화면에 모든 내용을 한꺼번에 펼치지 않는다. 가장 중요한 CTA는 **“오늘의 단어 모험 시작”**이다.

# 3. 이미지 중심 단어 카드 UI — 최우선 디자인

## 3.1 기본 카드 구조

단어 카드의 기본 레이아웃은 아래 순서를 따른다.

```text
┌────────────────────────────────────┐
│ 오늘의 단어  08 / 20       ★ 난이도 │
├────────────────────────────────────┤
│                                    │
│          [대표 연상 이미지]         │
│       단어 뜻을 장면으로 표현       │
│                                    │
├────────────────────────────────────┤
│             alleviate              │
│          /əˈliːvieɪt/              │
│        완화하다 · 덜어주다          │
│                                    │
│ [🔊 발음 듣기]       [느리게 듣기]  │
├────────────────────────────────────┤
│ 💡 기억 장면                         │
│ 무거운 돌을 들어 올려 고통을 덜어   │
│ 주는 장면을 떠올려 보세요.          │
│                                    │
│ [연상 이야기 보기] [어근 분석]      │
├────────────────────────────────────┤
│         [뜻 가리고 기억하기]        │
└────────────────────────────────────┘
```

위 와이어프레임은 구조 예시다. 실제 Compose 화면은 기기 크기에 맞춰 스크롤과 반응형 배치를 적용한다.

## 3.2 카드 디자인 규칙

- 이미지가 카드의 시각적 중심이 되도록 한다. 이미지가 없는 경우 단색 빈 공간을 남기지 말고 의미 기반 일러스트/아이콘/텍스트 힌트로 대체한다.
- 영어 단어는 이미지 다음으로 가장 큰 텍스트로 표시한다.
- IPA, 품사, 뜻은 정보 위계를 구분한다.
- 연상 스토리는 1~2문장으로 짧게 표시한다.
- 어근/접두사/접미사 정보는 검증된 경우에만 보여준다.
- 발음 재생 버튼은 한눈에 찾을 수 있도록 한다.
- 뜻을 공개하기 전/후 카드 상태가 명확해야 한다.
- 카드 좌우 스와이프는 보조 조작으로 제공할 수 있지만, 필수 기능을 스와이프만으로 숨기지 않는다.
- 카드 전체에 클릭 이벤트를 걸어 내부 버튼과 충돌시키지 않는다.
- 터치 영역 최소 48dp, 카드 간격 12~16dp, 카드 패딩 16~20dp를 기준으로 한다.
- 작은 화면에서 이미지와 단어가 잘리거나 지나치게 작아지지 않아야 한다.
- 장식용 그라데이션/3D 효과보다 이미지·단어·행동 버튼의 명확성을 우선한다.

## 3.3 카드 상호작용

학습 모드에 따라 앞면/뒷면이 달라야 한다.

### 학습 모드
- 앞면: 이미지 + 영어 단어 + 발음
- 뒷면: 뜻 + 기억 장면 + 예문 + 연상 설명

### 회상 모드
- 앞면: 이미지 또는 한국어 뜻/상황만 표시
- 사용자가 영어 단어를 떠올린 후 정답 확인
- 뒷면: 영어 단어 + IPA + 예문

### 듣기 모드
- 앞면: 음성만 재생하거나 발음 버튼을 제공
- 사용자가 들은 단어를 선택/입력
- 뒷면: 정답과 발음 차이 피드백

### 문장 모드
- 앞면: 예문 빈칸 또는 문장 속 의미 힌트
- 뒷면: 정답 단어와 자연스러운 해석

정답을 보기 전에는 사용자가 먼저 기억을 꺼내는 행동을 하도록 유도한다.

# 4. 이미지 수집·생성 시스템

## 4.1 목표

각 단어에는 의미를 즉시 연상할 수 있는 대표 이미지 1개를 우선 연결한다. 중요한 고빈출 단어와 사용자의 오답 단어는 추가 이미지/장면을 제공할 수 있다.

이미지는 장식이 아니라 단어 의미를 기억하게 하는 학습 자산이다.

## 4.2 이미지 획득 우선순위

다음 순서로 이미지 공급 전략을 구현한다.

1. 프로젝트에 이미 포함된 적합한 이미지 자산 재사용
2. 라이선스와 출처가 확인되는 공개 이미지/일러스트 소스
3. 사용 권한이 확인된 이미지 생성 API 또는 자체 생성 파이프라인
4. 위 방법이 불가능하면 로컬 기본 일러스트/아이콘/색상 장면으로 대체

외부 이미지 검색 결과를 무단으로 크롤링하거나 저작권이 불명확한 이미지를 앱에 저장하지 않는다. 상용 앱에 사용할 수 있는 라이선스인지 확인하고, 출처/라이선스/저작자/수집일을 기록한다.

## 4.3 생성 이미지 가이드

AI 이미지 생성은 단어 의미를 정확하게 전달하는 교육용 일러스트 스타일로 통일한다.

- 기본 비율: 1:1 정사각형
- 주요 피사체 1개 또는 명확한 상황 1개
- 배경은 단순하게, 핵심 행동은 크게
- 단어 자체의 철자를 이미지에 넣지 않는다. 이미지 안의 글자는 오탈자/왜곡 위험이 있으므로 UI 텍스트로 별도 표시한다.
- 복잡한 콜라주, 무관한 장식, 과도한 디테일 금지
- 한 단어에 여러 의미가 있으면 대표 의미별 이미지가 필요할 때만 복수 이미지 사용
- 추상 단어는 개념을 상징하는 구체적 장면으로 표현하되, 뜻을 왜곡하지 않는다.
- 이미지가 단어의 부정확한 의미를 암시하지 않는지 검수한다.

예:
- alleviate: 무거운 짐을 내려놓고 안도하는 사람
- resilient: 강하게 눌렸다가 다시 튀어 오르는 공
- fluctuate: 오르내리는 파도와 그래프
- ambiguous: 두 갈래 길 앞에서 선택을 망설이는 상황
- sustainable: 나무·에너지·순환 구조가 지속되는 장면

위 예시는 이미지 연상 방향이며, 단어 의미 자체를 대체하지 않는다.

## 4.4 이미지 데이터 모델

기존 `VocabWord` 호환성을 우선한다. 이미지 속성을 기존 모델에 직접 추가할지 별도 `VocabMediaAsset` 매핑 테이블/컬렉션으로 분리할지 기존 저장 구조를 조사해 결정한다.

최소 필드:
- `wordId`
- `assetId`
- `imageUrl` 또는 로컬 asset 경로
- `thumbnailUrl`
- `sourceType` (bundled / generated / licensed_external / fallback)
- `sourceName`
- `sourceUrl`
- `licenseName`
- `creator`
- `promptVersion` (생성 이미지인 경우)
- `reviewStatus` (pending / approved / rejected)
- `createdAt`
- `updatedAt`
- `contentHash`

원본 이미지와 썸네일을 구분한다. 화면에서는 썸네일을 먼저 로드하고 필요 시 원본을 로드한다.

## 4.5 저장·캐시·오프라인

- 이미지 URL을 매 화면 진입마다 새로 다운로드하지 않는다.
- 캐시 키는 wordId와 asset 버전을 기준으로 한다.
- 로컬 캐시를 사용해 최근 학습 단어는 오프라인에서도 표시한다.
- 이미지 다운로드 실패 시 카드가 깨지지 않고 fallback UI를 표시한다.
- 대량 이미지 수집 시 동시 다운로드 수, 파일 크기, 재시도 횟수, 저장 공간을 제한한다.
- 중복 이미지와 중복 요청을 방지한다.
- 이미지 교체 시 캐시 무효화 정책을 적용한다.
- 이미지 다운로드가 단어 학습 시작을 막지 않도록 비동기 처리한다.

## 4.6 이미지 수집 관리자/검수 도구

가능하다면 개발자용 관리 기능 또는 별도 스크립트로 다음 작업을 지원한다.

- 이미지가 없는 단어 목록
- 이미지 생성/수집 대기열
- 단어별 이미지 미리보기
- 승인/거절
- 출처/라이선스 확인
- 중복 이미지 감지
- 실패 재시도
- 이미지 일괄 업로드
- 단어별 이미지 상태 통계

AI가 생성한 이미지가 자동으로 상용 배포되는 구조로 만들지 않는다. 품질 검수 상태를 거치게 한다.

# 5. 기억 연상 엔진 고도화

기존 `VocabMnemonicEngine.kt`를 확장한다.

## 5.1 구조화된 연상 결과

기존의 단순 문자열 반환을 점진적으로 구조화한다.

예상 데이터:
- `wordId`
- `sceneTitleKo`
- `sceneDescriptionKo`
- `visualPromptEn`
- `visualPromptKo`
- `meaningAnchorKo`
- `soundAssociationKo`
- `morphemeBreakdown`
- `exampleSentence`
- `memoryQuestion`
- `confidence`
- `sourceType`
- `needsHumanReview`

현재 `MnemonicGuide`를 바로 삭제하지 않는다. 기존 호출부와 호환 어댑터를 제공한다.

## 5.2 연상 생성 규칙

- 의미와 직접 연결되는 장면을 만든다.
- 소리 연상은 실제 발음과 의미를 연결하는 기억 보조 장치로만 표시한다.
- 한국어 억지 발음을 실제 어원/발음 정보처럼 표현하지 않는다.
- 어근 분석은 검증된 형태소 정보가 있을 때만 제공한다.
- 모르는 어원은 “어근 분석 자료 없음”으로 표시한다.
- 단어가 여러 뜻을 가질 경우 현재 학습 문맥의 뜻에 맞춘다.
- 스토리는 짧고 구체적이며 시각화 가능해야 한다.
- 유머와 과장은 허용하되 단어 의미는 왜곡하지 않는다.
- AI 생성 결과는 품질 상태를 기록하고 낮은 신뢰도 결과는 사용자에게 단정적으로 제시하지 않는다.

## 5.3 기억의 궁전 기능

단어를 주제별/장소별로 묶어 기억 공간에 배치한다.

예시 공간:
- 집: 방, 부엌, 현관
- 학교: 교실, 도서관, 운동장
- 여행: 공항, 호텔, 식당
- 자연: 숲, 바다, 산

사용자는 장소를 선택하고 해당 공간에 단어 카드를 배치한다. 각 장소는 5~10개 단어 정도로 시작하고, 너무 많은 단어를 한 장소에 밀어 넣지 않는다.

기능:
- 장소 선택
- 단어 배치
- 장소별 이미지/장면 보기
- 공간을 이동하며 단어 회상
- 기억하지 못한 단어 재배치/재학습
- 사용자가 만든 개인 연상 메모 저장

초기 버전은 2D 카드형 장소 목록으로 구현한다. 3D 월드/복잡한 맵은 핵심 학습이 안정화된 후 검토한다.

# 6. 게임화 시스템: XP·코인·레벨·배지

## 6.1 재화 구분

기존 RPG 코인/보상 시스템의 저장 구조와 의미를 먼저 확인한다.

권장:
- XP: 학습 경험치. 레벨 상승용이며 소비하지 않는다.
- 코인: 상점/캐릭터/테마/꾸미기 아이템 구매용.
- 배지: 특정 성취 기록. 소비하지 않는다.
- 연속 학습일: 실제 학습 조건을 충족한 날짜만 인정한다.

기존에 같은 의미의 재화가 있으면 중복 생성하지 말고 통합 방안을 제시한다. 서로 다른 시스템이라면 화면에서 명확하게 구분하고 변환 규칙을 임의로 만들지 않는다.

## 6.2 보상 원칙

보상은 학습 품질과 연결한다. 단어를 무한히 넘기는 행동에는 보상을 주지 않는다.

초기 제안 값은 밸런싱을 위한 설정값이며 코드에 흩어 놓지 말고 `RewardConfig` 등 한 곳에서 관리한다.

| 행동 | XP 예시 | 코인 예시 | 지급 조건 |
|---|---:|---:|---|
| 새 단어 학습 완료 | 5 | 1 | 단어 학습 이벤트 1회 |
| 이미지 연상 확인 | 2 | 0 | 이미지/스토리 확인 후 회상 수행 |
| 뜻 가리고 정답 회상 | 5 | 2 | 정답 확인 이벤트 |
| 입력형 정답 | 8 | 3 | 정답 일치/허용 오타 정책 |
| 듣기 퀴즈 정답 | 6 | 2 | 음성 문제 정답 |
| 오늘 복습 완료 | 10 | 4 | due 단어 목표 달성 |
| 10개 단어 세션 완료 | 15 | 5 | 최소 학습량 및 회상 평가 충족 |
| 일일 미션 완료 | 20 | 8 | 미션별 검증 조건 충족 |
| 주간 목표 달성 | 60 | 20 | 주간 고유 학습/복습 조건 충족 |

중요:
- 위 숫자는 초기 제안이다. 실제 학습 소요 시간과 난이도를 테스트해 조정한다.
- 동일 이벤트 ID에 대한 중복 지급은 절대 허용하지 않는다.
- 한 단어를 반복해서 열어도 새 단어 학습 보상을 계속 받을 수 없다.
- 정답만 연속 클릭하는 방식으로 보상을 얻지 못하게 한다.
- 보상 지급은 UI가 아니라 ViewModel/Repository의 단일 검증 로직에서 처리한다.

## 6.3 XP 레벨 시스템

예시 레벨:
- Lv.1 단어 탐험가
- Lv.2 기억 수집가
- Lv.3 이미지 연상가
- Lv.4 어휘 사냥꾼
- Lv.5 문장 마스터
- Lv.6 기억의 건축가
- Lv.7 단어 챔피언

레벨은 XP 누적 기준으로 계산한다. 레벨별 필요 XP는 `LevelConfig`로 관리하고, 변경 가능한 밸런스 데이터로 분리한다.

레벨업 시:
- 짧은 애니메이션
- 획득한 배지/보상 표시
- 다음 레벨까지 남은 XP
- 새로 열린 기능이 있다면 명확한 설명

과도한 팝업으로 학습을 끊지 않는다.

## 6.4 보상 원장(ledger)

포인트 데이터는 잔액만 저장하지 말고 변동 이력을 보존한다.

필수 필드:
- `transactionId`
- `userId`
- `eventId`
- `eventType`
- `xpDelta`
- `coinDelta`
- `reason`
- `wordId` 또는 `missionId`
- `createdAt`
- `sourceSessionId`

필수 규칙:
- `eventId` 또는 멱등성 키로 중복 지급 방지
- 음수 잔액 방지
- 서버/로컬 동기화 충돌 정책
- 취소/정정은 기존 기록을 덮어쓰지 않고 보정 거래로 기록
- 포인트가 구매/현금 가치로 오인되지 않도록 표시
- 계정 간 포인트 이전은 기본적으로 지원하지 않음

오프라인 학습 보상은 로컬 큐에 기록하고, 온라인 복귀 후 중복 없이 동기화한다. 보상 검증은 가능한 한 서버 측에서도 수행한다.

# 7. 미션 시스템

## 7.1 미션 유형

### 일일 미션
- 오늘 새 단어 10개 배우기
- 이미지 연상 5개 확인하고 회상하기
- 틀린 단어 5개 다시 도전하기
- 영어 발음 5개 듣고 따라 말하기
- 어제 배운 단어 10개 복습하기

### 주간 미션
- 5일 학습 달성
- 고유 단어 50개 학습
- 취약 단어 30개 재회상
- 듣기 퀴즈 20문제 정답
- 기억의 궁전 장소 3곳 완성

### 스토리/탐험 미션
- 공항 장소의 단어 10개 수집
- 감정/심리 단어 10개 수집
- 수능 고빈출 단어 보스 도전
- 특정 어근/접두사 단어 묶음 정복

## 7.2 미션 카드 UI

각 미션은 카드형으로 표시한다.

- 미션 제목
- 짧은 설명
- 진행 상태: `3 / 10`
- 진행률 바
- 보상 XP/코인
- 시작/계속 버튼
- 완료 시 완료 상태 및 보상 수령 상태

미션 진행률은 실제 이벤트에서 계산한다. 화면을 다시 열 때마다 임의로 초기화하지 않는다.

## 7.3 미션 상태

- LOCKED
- AVAILABLE
- IN_PROGRESS
- COMPLETED
- CLAIMED
- EXPIRED

완료와 보상 수령을 분리한다. 완료 상태에서 보상 수령을 반복할 수 없어야 한다.

## 7.4 미션 생성 규칙

초기에는 규칙 기반 미션을 우선 구현한다. AI가 매일 임의로 미션을 만들게 하지 않는다.

- 사용자의 학년/난이도/학습 기록에 따라 목표 수 조정
- 이미 숙달한 단어만 반복하는 미션 방지
- 복습이 밀린 사용자는 복습 미션 비중 확대
- 신규 사용자는 쉬운 온보딩 미션 제공
- 하루 목표는 현실적으로 10~20분 내 완료 가능한 양부터 시작
- 사용자가 원하면 목표량을 조정할 수 있게 한다.

# 8. 단어 미니게임

학습과 직접 연결되는 짧은 게임을 제공한다. 모든 게임은 단어 학습 결과와 복습 스케줄에 반영되어야 한다.

## 8.1 그림 맞히기
- 그림을 보고 영어 단어를 4개 선택지 중 고른다.
- 오답 선택지는 품사/난이도/의미 혼동을 고려해 구성한다.
- 정답 후 뜻과 연상 장면을 짧게 보여준다.

## 8.2 기억 뒤집기
- 그림 카드와 영어 단어 카드를 짝짓는다.
- 단순 운으로 끝나지 않도록 완료 후 단어를 다시 회상한다.
- 너무 많은 카드를 한 번에 노출하지 않는다.

## 8.3 3초 회상 챌린지
- 이미지 또는 뜻을 표시한다.
- 짧은 시간 안에 영어 단어를 떠올려 입력/선택한다.
- 시간 초과는 학습 실패가 아니라 복습 대상으로 기록한다.
- 속도 점수보다 정확도와 회상 성공을 우선한다.

## 8.4 철자 조립
- 알파벳 타일을 순서대로 배치해 단어를 완성한다.
- 철자 힌트와 IPA를 단계적으로 제공한다.
- 정답 후 소리와 뜻을 다시 연결한다.

## 8.5 문장 속 단어 찾기
- 예문에서 빈칸을 채운다.
- 단어의 의미뿐 아니라 실제 문맥에서 쓰임을 확인한다.

## 8.6 보스 챌린지
- 일반 단어 5~10개를 학습/회상한 후 보스 퀴즈를 연다.
- 보스는 혼합 유형(그림/뜻/듣기/철자/문맥)으로 출제한다.
- 보스 실패 시 보상 몰수보다 취약 단어 복습 경로를 제공한다.
- 재도전은 가능하되 동일 보상 반복 지급은 방지한다.

# 9. 간격 반복 및 복습 스케줄

기존 `SMART_REVIEW`, `EBBINGHAUS_SM2` 트랙과 연결한다.

## 9.1 단어별 학습 상태

- NEW
- LEARNING
- REVIEW
- MASTERED
- SUSPENDED (사용자 숨김/제외)

## 9.2 회상 결과

사용자가 정답을 본 뒤 자기평가만 하는 방식에 의존하지 않는다. 퀴즈/입력/듣기 결과와 함께 다음 평가를 기록한다.

- AGAIN: 전혀 기억나지 않음
- HARD: 어렵게 기억함
- GOOD: 적절히 기억함
- EASY: 쉽게 기억함

## 9.3 스케줄러

기존 SM-2 구현 여부를 먼저 확인한다. 이미 동작하는 구현이 있으면 새 스케줄러를 중복 구현하지 않는다.

스케줄러는 다음 값을 관리한다.
- `repetition`
- `intervalDays`
- `easeFactor`
- `dueAt`
- `lastReviewedAt`
- `lapseCount`
- `consecutiveCorrect`
- `lastRecallGrade`

초기 복습 간격은 예시로 10분/1일/3일/7일/14일을 사용할 수 있지만, 실제 스케줄은 사용자 응답과 기존 알고리즘을 기준으로 계산한다. “해마 골든타임”을 의학적·신경과학적 보장처럼 표현하지 않는다.

## 9.4 복습 큐

단어 홈에 다음을 노출한다.
- 지금 복습할 단어 수
- 오늘 예정 단어 수
- 기한이 지난 단어 수
- 취약 단어 수

복습은 새 단어 학습보다 먼저 제안할 수 있다. 다만 사용자가 새 단어를 학습하고 싶어 하는 선택도 막지 않는다.

## 10.2 데이터 무결성

- 학습 기록과 보상 지급을 같은 이벤트 흐름에서 처리한다.
- 앱 강제 종료 후에도 완료된 학습과 지급된 보상이 복구되어야 한다.
- 중복 클릭/네트워크 재시도/동기화 재실행으로 보상이 중복 지급되지 않아야 한다.
- 단어 ID가 변경되어도 기존 학습 이력이 유실되지 않도록 한다.
- 데이터 마이그레이션은 이전 버전 사용자 데이터와 호환되어야 한다.
- 로컬 저장 성공과 서버 동기화 성공을 구분한다.

# 11. 카드형 UI 디자인 시스템 상세

## 11.1 색상 역할

기존 프로젝트의 `StudioCobalt`, `StudioCoral`, `StudioIris`, `GlacierCyan`, `TrophyGold` 등 테마 토큰을 우선 재사용한다.

의미 색상:
- 학습/진행: 기존 주 색상
- 정답/완료: 기존 성공 색상
- 오답/주의: 기존 오류/코랄 계열
- 보상/XP/배지: 골드 계열
- 이미지/기억: 보조 청록/보라 계열

색상은 의미가 일관되어야 하며 단순 장식 목적으로 무작위 지정하지 않는다.

## 11.2 카드 종류

1. 오늘의 학습 카드
2. 이미지 단어 카드
3. 복습 카드
4. 미션 카드
5. 보스 도전 카드
6. 레벨/XP 카드
7. 배지/수집 카드
8. 기억의 궁전 장소 카드

모든 카드에 같은 레이아웃을 강요하지 말고, 콘텐츠의 우선순위에 맞춰 카드 높이와 이미지 비율을 조절한다.

## 11.3 홈 화면 시각 위계

첫 화면에서 가장 먼저 보이는 요소:
- 오늘의 진행률
- 오늘의 단어 목표
- 복습해야 할 단어 수
- 오늘의 핵심 미션
- 학습 시작 CTA

XP/코인/레벨은 상단에 작고 명확하게 배치한다. 재화가 학습 목표보다 더 강조되지 않게 한다.

## 11.4 애니메이션

- 카드 뒤집기: 짧고 부드럽게
- 정답: 짧은 성공 피드백
- 오답: 실패 낙인 대신 재도전 유도
- 보상: 보상 수치와 이유를 함께 표시
- 레벨업: 사용자가 원할 때 건너뛸 수 있게 한다.
- 접근성의 애니메이션 축소 설정을 존중한다.
- 애니메이션 중 연속 탭으로 이벤트가 중복되지 않게 한다.
